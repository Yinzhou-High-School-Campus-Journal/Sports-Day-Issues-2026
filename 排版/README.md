# 排版

本目录是两期编辑部版的制作程序：Markdown 稿件 → HTML → Chromium 打印成 PDF，再拼入另做的扉页，写入书签、页码标签与文件信息。

| 位置 | 内容 |
| --- | --- |
| [第一期](<第一期/README.md>) | 《云图试骏》内页：版式规格、卷首语页底的人员表。 |
| [第二期](<第二期/README.md>) | 《骋风逐曜》内页：扉页背面的人员表、目录后的空白页、左右页页眉。 |
| [封面](<封面/README.md>) | 两期封面与扉页。 |
| [fonts](<fonts/README.md>) | 字体与指纹清单。 |
| `typeset.py` | 两期内页共用的排版程序：稿件解析、配图、版面测量与留白配图。 |
| `art.py` | 两期共用的线描插图图样。 |
| `release.py` | 完整制作入口。 |
| `render.cjs` | 两期内页共用的打印脚本：检查图片、字体与版心宽度，处理行尾标点伸出栏外。 |
| `preflight.py` | 检查依赖版本，生成并校验字体，检查拼页文件和 PDF 里嵌入的字体，保证构建不改动来源稿。 |
| `pdf_metadata.py` | PDF 文件信息、页码标签与书签校正，两期和封面共用。 |
| `browser.cjs` | 共用的浏览器启动配置。 |
| `tests/` | 回归检查。 |

### 运行

需要 Python 3.12、Node.js 24 与 npm（具体版本见本目录的 `.python-version`、`.node-version` 和 `package.json`）。在本目录安装一次：

```bash
cd 排版
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
npm ci
npx playwright install chromium
```

Linux 上缺浏览器要用的系统库时，最后一步改用 `npx playwright install --with-deps chromium`（发布用的工作流就这样装）；Windows 上用 `py -3.12 -m venv .venv` 建环境，用 `.venv\Scripts\activate` 激活。

要用本机已有的浏览器，可设环境变量 `CHROMIUM_EXECUTABLE` 指向它；版本不是 Chromium 141 时，不保证与已发布的版面一致。

完整制作两期，或只做一期：

```bash
python release.py
python release.py 第一期
```

首次运行会生成正文用的静态字重和方正恒仿宋的补字（约一分半钟），之后直接复用。输出都在各制作目录内，不提交：

| 目录 | 输出 |
| --- | --- |
| `封面/` | `第一期封面.pdf`、`第一期扉页.pdf`、`第二期封面.pdf`、`第二期扉页.pdf` 及同名 PNG |
| `第一期/` | `第一期内页.pdf`（发行用，扉页加正文）、`第一期正文.pdf`、`第一期（含封面预览）.pdf`、`第一期.html`、`第一期版面.json`、`images/` |
| `第二期/` | `第二期内页.pdf`（发行用）、`第二期.html`、`第二期版面.json`、`images/` |

`版面.json` 记录每篇的起止页、印出的页码、末页留白行数和配图行数，可用来核对目录。

同一提交在同一操作系统上重新制作，PDF 逐字节相同，可以直接用 `sha256sum` 比对；换了系统，页码和竖排文字会上下差 0.75 pt。前提是用锁定的 Chromium（不设 `CHROMIUM_EXECUTABLE`），并且日期相同：日期取最后一次提交的时间（见「文件信息」），用不带 `.git` 的源码包制作时须自己设 `SOURCE_DATE_EPOCH`，否则取当前时间。要重建 `2026.10.10`，在 Linux 上检出这个 tag 制作；用源码包则设 `SOURCE_DATE_EPOCH=1791605982`。Release `2026.10.7` 的编辑部版早于这一点和补字，只能逐页比对。

回归检查（最后一项会启动浏览器，须先生成字体、安装浏览器）：

```bash
python -m unittest discover -s tests
node --test tests/browser.test.cjs
node tests/check_browser_geometry.cjs
```

### 发布

发行文件由 GitHub Actions 的「制作编辑部版」工作流（[`.github/workflows/build.yml`](<../.github/workflows/build.yml>)）在 Ubuntu 24.04 上制作。发新版时：

1. 把仓库文档里指向 Release 的下载链接改成新版本的 tag（用日期，如 `2026.10.10`），提交到 `main`。
2. 在仓库的 Actions 页选「制作编辑部版」，对 `main` 点 Run workflow。工作流按锁定的版本安装 Python、Node、依赖与 Chromium，跑回归检查，连做两遍核对逐字节相同，再为四个发行文件生成构建来源证明。
3. 在运行页下载产物 `Sports_Day_Issues_2026_ED`（已按发行名命名的四个 ED 文件和 `SHA256SUMS`），以这次运行所用的提交为 tag 目标新建 Release，上传这四个文件，以及上一版未变的两份 `Print` PDF 和两张 `Cover_Print` 图片，共 8 个文件（`SHA256SUMS` 只用于核对，不上传）；说明里附上运行链接。

`gh attestation verify <文件> -R Yinzhou-High-School-Campus-Journal/Sports-Day-Issues-2026` 可以核对文件出自哪次运行、哪个提交；也可以在 Linux 上用同一提交重新制作，比对 SHA-256。仓库归档后只读，工作流不能再运行，需要时可以 fork 后照样运行。

### 流程

1. 读取一期的稿件（前置内容、各板块导读与文章、卷尾语），生成 HTML。
2. Chromium 打印成 PDF；从书签读出每篇的起止页，回填目录页码。
3. 量出每篇末页的留白行数，按 `build.py` 里 `FILLS` 的配置放插图，再排，直到版面不再变化（最多八遍，仍不稳定就报错）。
4. 拼入扉页，写入书签、页码标签与文件信息。

每期目录里的 `build.py` 只放本期的配置、目录、人员表与拼页，`style.css` 定义版式。第二期的程序在第一期基础上增加了左右页页眉、人员表页和卷尾语，下期可以从第二期的程序改起。`python art.py [图样名]` 把线描图样输出到 `art预览/`，可以单独预览。

### 稿件写法

```markdown
# 标题

2503 作者姓名

——副标题（可选）

---

正文段落……西文书名用 *斜体*，不加书名号。

### 中标题

> 引文或歌词，每行末尾两个空格  
> ——出处, *Title*

诗行，每行末尾两个空格  
下一行

![说明](../../资产/图片.jpeg)
```

- 文件标题用一级，正文小节从三级开始。
- 整篇都是诗行时，单栏居中排；诗里单独成段的短句（如叠句）并入诗行。
- 篇首单独一段「引文」——出处，排成题记。
- 文末连着两张以上的图，排成通栏并排的图组。
- 引号用「」，嵌套用『』；破折号 `——`、省略号 `……`。
- 板块目录里的 `00_导读.md` 排成板块起始页。
- 人员表每行「职务：姓名　姓名」，姓名之间用全角空格。

### 配图

每期 `build.py` 里的 `FILLS` 按文章配置留白处的插图：`art` 为 `art.py` 里的图样名，按文章内容画；`photo` 为照片，钟楼、校园实景这类画不好的用视频截图。第一遍排版后量出每篇末页还空几行，插图高度按剩余行数取整；`where: "head"` 的图放在作者行下方，用来把只溢出几行的文章撑成匀称的两页。

照片一律转灰度（自动色阶、提亮中间调以抵消网点扩大）。视频截图按原比例取高（`max`），多出的行留在图上方、图沉到页底（`anchor: "bottom"`），不硬裁成方图。同一类画面（跑道、钟楼、群山、落日）全书尽量只出现一两次。

### PDF 书签、页码标签与文件信息

- 书签由 Chromium 按 HTML 标题生成，但个别标题的文字会被重复拼接（第一期《凌汐》的「（三）」曾变成「（三（三））」）。拼页时书签文字一律改取 HTML 标题，条数对不上就报错。目录页里的板块名也会生成书签，都指向目录页，与后面各板块的书签重复，拼页时去掉。
- 页码标签与印出的页码一致：不计页数的页（第一期的扉页，第二期的扉页、人员表、目录和空白页）直接用中文标签，其余用阿拉伯数字。
- 文件信息：标题为「校运会特刊 + 期次 + 期名 + 输出类型」，作者为「《鄞年・思叙》编辑部」，主题为「鄞州中学第四十四届暨鄞州蓝青高级中学第二十九届校园运动会特别刊物」；实际的 PDF 生成器原样保留。创建与修改日期取环境变量 `SOURCE_DATE_EPOCH`，未设置时取仓库最后一次提交的时间（UTC）；文件标识 `/ID` 按内容计算，不沿用 Chromium 按时间生成的标识。

### 经验与注意事项

- 浏览器：用 `package-lock.json` 锁定的 Playwright 1.56.1 及其 Chromium 141（141.0.7390.37）排版，能重现已发布的编辑部版内页（文字、断行和字符位置一致）；换用其他版本可能改变断行。
- 字体：可变字体和 CFF 轮廓的 OTF 会被 Chromium 打印成 Type 3 字体，印刷预检容易报错，正文须用实例化后的静态 TrueType。Linux 默认的字体微调会把 14 px 正文里全角省略号的宽度推到 15 px、改变断行，所以浏览器启动时关闭微调（`--font-render-hinting=none`）。方正恒仿宋缺的字由 `preflight.py` 补上：「晅」「臙」从同一字体的左右结构字里取部件原位拼成，如「臙」取「胭」的月旁和「嬿」的燕，部件相撞时只把右部件横向收窄，高度不变；「・」借用「·」的字形。排版前逐字检查稿件，缺字即报错；Chromium 每次出 PDF 后再查一遍嵌入的字体，出现仓库以外的字体（仓库字体缺字时 Chromium 会改用本机字体，封面的子集字体也一样）或 Type 3 字体同样报错，不会悄悄换成别的字体。
- 标点挤压：Chromium 141 尚不支持行尾压缩（`text-spacing-trim: trim-both`）；行尾连续标点可能伸出栏外，`render.cjs` 会逐段检查，伸出的段落关掉挤压。
- 第二期付印版是校方用 WPS 直接改 PDF、文印室付印前又改过的，由此带来的问题见[两版比较](<../版本记录/第二期两版比较.md>)第 6—9 节。下期最好把修改意见交回排版程序重新出 PDF。
